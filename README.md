# Subnets Add Subtract

A C utility for combining IPv4 CIDR lists and optionally subtracting a second list. It
writes the resulting address space as a compact CIDR set.

Subnets add subtract - утилита на C для объединения списков IPv4 CIDR, вычитания необязательного второго списка и сохранения оставшегося адресного пространства в компактном виде CIDR.

## Описание

Вход `-a` задаёт сети, которые нужно включить в рабочий набор, а `-s` - сети, которые нужно из него удалить. Получившийся набор IPv4 адресов снова компактно представляется в виде CIDR и записывается в `result.txt`.

Реализация делит пространство IPv4 адресов между рабочими потоками и использует префиксное дерево для построения компактного итогового вывода. Количество потоков должно быть степенью двойки.

## Разработка и проверка изменений

**Опорные символы для изменения поведения:**

1. `add_to_node`, `save_one_addr`, `save_cidr`, `dump_tree` - формирование префиксного дерева и
   выдача CIDR; не смешивайте его с операциями над битовой картой IPv4.

**Основные точки изменения:**

- `src/subnets.c` - разбор сетей IPv4, объединение и вычитание диапазонов;
- `CMakeLists.txt` - сборка утилиты.

**Поток данных:** после разбора `-a` и необязательного `-s` программа
помечает адреса в общей битовой карте IPv4: добавление выставляет биты,
вычитание очищает. Затем `process_thread_func()` обрабатывает части
пространства между барьерами pthread; префиксное дерево используется
для свёртки результата в CIDR. Изменяя формат выхода или алгоритм
свёртки, проверьте границы частей и последующую обработку `result.txt`.

**Граница CIDR-парсера:** длина префикса должна находиться в диапазоне
`0..32`. Код читает её через `sscanf()` без проверки диапазона, а затем
использует в сдвигах при вычислении маски и размера подсети. Значения
больше `32` могут вызвать неопределённое поведение; проверяйте входные
списки до запуска. `inet_addr()` вызывается без проверки результата;
ошибочный IPv4 текст может дать `INADDR_NONE`, неотличимый в этом коде от
`255.255.255.255`. Проверяйте и адрес, и префикс до передачи в утилиту.
Даже маленький список может потребовать полный проход
по пространству IPv4 при формировании результата.

**Инварианты:** вход ограничен IPv4, число потоков - степень двойки не
больше `64`, а битовая карта всегда охватывает все `2^32` адресов.
`result.txt` перезаписывается. Текущий парсер использует `fscanf()`
без ограничения ширины строки и не проводит полную проверку префикса:
документация не должна обещать безопасную обработку произвольного ввода.

**Файлы сборки:** `CMakePresets.json` содержит профили конфигурации, а `CMakeLists.txt` управляет в том числе настройками анализаторов и санитайзеров. Не путайте параметры сборки с алгоритмом обработки IPv4.

**Проверка изменений:** для операций над множествами важны полный охват,
пустой результат, вложенные сети, пересечения и границы `0.0.0.0/0`,
`255.255.255.255/32`. Отдельных автоматических тестов в репозитории нет;
это перечень случаев для будущей проверки, а не утверждение о её выполнении.

## Сборка

```sh
cmake --preset release
cmake --build --preset release
```

Исполняемый файл:

```text
build/release/subnets
```

## Использование

```text
Commands:
  Required parameters:
    -t  "x"          Thread count
    -a  "/test.txt"  Path to the subnets to add
  Optional parameters:
    -s  "/test.txt"  Path to the subnets to subtract
```

Пример:

```sh
./build/release/subnets -t 8 -a add.txt -s subtract.txt
```

Результат сохраняется в:

```text
result.txt
```

## Формат входа

Входные файлы содержат IPv4 сети в CIDR notation, по одной сети на строку. Сначала объединяются сети из `-a`, после чего из полученного множества исключяются сети из `-s`.

Число потоков должно быть степенью двойки: `1`, `2`, `4`, `8`, `16`, `32` или
`64`. Значения `0`, больше `64` и не являющиеся степенью двойки отклоняются.

**Ресурсы и побочные эффекты:** перед обработкой программа выделяет битовую карту
всего пространства IPv4 (около 512 МиБ при 8-битном байте), независимо от
размера входных списков. Файл `result.txt` в текущем рабочем каталоге
открывается на запись с перезаписью. Параметр `-s` необязателен, но `-a`
и `-t` обязательны. Парсер исходных CIDR не выполняет полную строгую
валидацию длины префикса и всех входных строк; для недоверенных данных
валидацию необходимо усилить до использования утилиты.
